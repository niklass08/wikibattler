# WikiTCG

A trading-card game built on Wikipedia. Every article is a card:

- **Strength** ← number of internal links in the article
- **Defence** ← byte length of the article
- **Rarity** (common / uncommon / rare / mythic) ← the article's popularity (pageviews)

Two screens: **open packs** (7 cards, guaranteed 4 common / 2 uncommon / 1 rare-or-better)
and **view your collection**. Fully client-side — no backend, no API keys. Your
collection lives in `localStorage`.

See [`PLAN.md`](./PLAN.md) for the full design + API notes.

## Develop

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # unit tests (rarity + pack logic)
npm run check      # svelte-check + tsc for the build script
npm run build      # -> dist/  (static, deploy anywhere)
```

## Card data

The game runs on `src/data/pools.json`, generated by a build script that crawls the
Wikimedia APIs. A small fixture (`src/data/pools.sample.json`) is used automatically
when `pools.json` is empty, so the app works before the first crawl.

```bash
npm run pools                 # ~4000 cards (takes a few minutes)
TARGET=800 npm run pools      # smaller / faster
MONTHS_BACK=6 npm run pools   # months of "most viewed" lists to seed rarities from
```

Intermediate API responses are cached in `scripts/.cache/` so re-runs are cheap.
After a run, check `scripts/.cache/pools.summary.json` and tune `RARITY_THRESHOLDS`
in `src/lib/rarity.ts` if the rarity split looks off. **Commit `src/data/pools.json`.**

## Deploy

Static output. For a GitHub Pages project site, build with the repo name as base:

```bash
VITE_BASE=/wikitcg/ npm run build
```

`.github/workflows/deploy.yml` does this on push to `main`.
